# labu-loom 发布与更新方案

## 一、已确认边界

- 正式代码仓库：`https://github.com/dengweiqiang22/labu-loom`
- 当前发布平台：Windows x64
- 发布载体：GitHub Releases
- 更新清单地址：`https://github.com/dengweiqiang22/labu-loom/releases/latest/download/latest.json`
- 发布触发方式：推送 `v*` 标签后，由 GitHub Actions 读取 `docs/版本日志/<标签>.md`、构建并创建草稿 Release；人工核对版本说明、安装包、签名和更新清单后再发布。

旧项目的 UpgradeLink、Gitee 镜像和 `ayangweb/BongoCat` 更新地址不再使用。

## 二、签名分层

### 2.1 Tauri 更新签名

Tauri 更新签名用于验证自动更新产物的完整性和来源，是启用自动更新前的强制条件。

- 为 labu-loom 单独生成一套密钥，不复用上游项目密钥。
- 公钥写入 `src-tauri/tauri.conf.json`，可随源码公开。
- 私钥不得进入仓库、构建日志或任务文档。
- CI 仅通过 GitHub Actions Secrets 注入：
  - `TAURI_SIGNING_PRIVATE_KEY`
  - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`
- 私钥还需要一份加密的离线备份；丢失私钥后，已安装版本无法信任由新密钥签出的更新。

当前密钥状态：

- 专用密钥已生成，公钥已写入 Tauri 配置。
- 加密私钥位于 `%USERPROFILE%\.tauri\labu-loom\labu-loom.key`。
- 随机密码以当前 Windows 用户可解密的 DPAPI 密文保存在同目录的 `labu-loom.password.dpapi`。
- 本地签名冒烟测试和 Windows NSIS updater 签名构建已通过。
- GitHub Actions Secrets 仍需在正式仓库中设置，禁止把本地密钥文件或解密后的密码提交到 Git。

应用只提供用户主动点击的“检查更新”入口，不默认检查或弹出更新提醒，符合低打扰产品边界。

### 2.2 Windows Authenticode 签名

Windows 可执行文件和安装器的 Authenticode 代码签名与 Tauri 更新签名是两套独立机制。0.1 已确认暂不采购或配置 Authenticode 证书；未签名安装包可以运行，但可能触发 SmartScreen 警告。

证书、私钥和密码不得进入仓库。具体 CI 接入方式需要在证书形态（本地 PFX、云签名或硬件密钥）确定后单独评审。

## 三、发布门禁

1. 本地执行 `corepack pnpm install --frozen-lockfile`。
2. 执行前端 lint、生产构建、Rust 格式检查和 workspace check。
3. 确认版本号与 `v*` 标签一致。
4. 人工编写 `docs/版本日志/vX.Y.Z.md`，只保留用户可感知变化、必要的兼容说明和安装提示，不用提交标题拼接正文。
5. 确认更新签名 Secrets 已配置且离线备份可恢复。
6. 推送标签，等待 Windows x64 workflow 读取同名版本日志并生成草稿 Release；文件缺失或为空时 workflow 必须失败。
7. 在 Windows 实机安装草稿产物，验证启动、托盘、偏好设置和从上一正式版本更新。
8. 核对草稿正文以及 `latest.json` 的版本、下载地址和签名后，人工发布 Release。

任何步骤失败时不得发布，也不得用关闭签名校验的方式绕过。
