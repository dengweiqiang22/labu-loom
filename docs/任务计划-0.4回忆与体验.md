# 0.4 回忆与体验完善任务计划

## 一、目标

在 `0.3.7` 已有的日、周、月聚合和结构化记忆之上，建立面向用户的共同回忆体验，并完善连续工作暗示、可选休息提醒、多显示器和窗口边界。核心体验继续保持离线、本地、低打扰，不引入自由文字聊天、在线模型或生产力评分。

本阶段版本基线为 `0.4.0`，计划完成后版本为 `0.4.7`。

## 三、实施顺序

1. RE-01 先提供不依赖界面的只读展示模型，作为页面和自然总结的共同数据源。
2. RE-02 接入现有记忆页，默认展示共同回忆，同时保留完整的查看、修改、忘记和清除入口。
3. RE-03 至 RE-05 依次完成自然表达、动作暗示和用户主动开启的明确提醒。
4. RE-06 可与表达能力并行开发，但必须在最终 Windows 验收前完成。
5. RE-07 统一处理界面细节、错误恢复和构建体积，RE-08 完成阶段收口。

## 五、产品与数据边界

- 共同回忆不是生产力仪表盘，不显示分数、排名、打卡、完成率或负面评价。
- 展示模型只消费日、周、月聚合与结构化记忆，不读取应用名称、窗口标题、屏幕、文档或剪贴板。
- 共同回忆最多展示少量近期重点；完整的修改、忘记和清除能力继续放在记忆管理视图。
- 自然总结使用代码内置的固定模板和结构化参数，不保存最终渲染文案。
- 连续工作时长只允许在当前运行期间短暂存在于内存；长期存储仍保持日级聚合。
- 明确休息提醒默认关闭，安静模式、窗口穿透或用户关闭互动时不得出现。
- `WIN-01` 微信输入法 CrashRpt 弹窗继续作为外部问题观察，在最终实机验收中回归。

## 六、完成定义

- 用户可以看到温和、可忽略的共同回忆，而不是原始数据表。
- 所有自然表达都能追溯到结构化记忆或聚合周期，并支持现有删除流程。
- 关闭统计或清除数据后，共同回忆和总结同步消失，不保留派生副本。
- 提醒和动作暗示不会破坏拖动、穿透、安静模式或行为调度上限。
- 显示器布局、缩放或连接状态变化后，宠物与设置窗口仍能恢复到可见区域。
- Windows 日志、Store 和崩溃诊断中不出现原始键鼠事件或自由文字。

## 七、当前实施结果

### 7.1 共同回忆展示模型

- 已完成 RE-01，版本提升到 `0.4.0`；新增纯函数展示模型，统一组合日、周、月聚合与结构化记忆。
- 模型只计算陪伴记录覆盖天数、既有聚合累计、可用周期范围和最多 4 条近期结构化记忆，不新增 Store 字段或派生持久化副本。
- 近期记忆按日级更新时间稳定排序；输入数组和记忆对象保持只读，不会因为页面展示改变原始数据。
- 空数据返回明确空态，数据清除后无需额外清理展示缓存；后续页面与自然总结共用这一数据入口。

### 7.2 共同回忆页面

- 已完成 RE-02，版本提升到 `0.4.1`；记忆页面默认展示共同回忆，并保留独立的记忆管理视图。
- 页面只展示陪伴记录覆盖天数、可用聚合周期和最多 4 条近期结构化记忆，不展示分数、原始输入或精确活动时间线。
- 既有分类修改、单条忘记、分类清除和全部清除入口保持不变；无数据时展示温和空态，不创建派生持久化副本。
- 已补齐简体中文、繁体中文、英文、葡萄牙文和越南文文案，并在 Windows 调试实例中确认应用进程正常响应。
