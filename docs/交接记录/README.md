# labu-loom 交接记录说明

## 一、用途

本目录保存 Codex、Cursor 或其他开发工具之间的阶段性交接记录。交接文档用于说明交接当时的真实仓库状态、已经完成的验证、尚未完成的工作和必须继续遵守的项目约定，不能用提交记录或聊天摘要代替。

## 二、文件规则

- 每次交接新建文件，不覆盖历史记录。
- 文件名使用 `YYYY-MM-DD-来源至接收方.md`；同一天发生多次时追加二十四小时制时间，例如 `2026-09-05-1430-Cursor至Codex.md`。
- 文档使用中文，命令、路径、分支、标签和代码标识使用反引号。
- 只记录完成交接所需的信息，不复制密钥、令牌、签名私钥、密码、个人数据或本机日志内容。
- Git 状态、提交、标签、版本和验证结果必须在写文档前重新检查，不能沿用可能过期的聊天结论。

## 三、必填内容

每份交接文档至少应包含：

1. 交接时间、来源、接收方、仓库路径和当前分支。
2. 当前提交、版本、标签、远程同步和工作区状态。
3. 已完成事项及其验证证据。
4. 未提交或不属于本次工作的文件，明确说明保留方式。
5. 下一任务、验收标准、建议入口和明确不做的事项。
6. 已知问题、外部阻塞、尚未验证的推断和回滚风险。
7. 分支、提交、版本、发布、验证、产品和隐私约定。
8. 接收方完成工作后应回传的内容。

## 四、接收与回传

接收方开始修改前必须先阅读仓库根目录 `AGENTS.md`，以及交接文档列出的相关项目文档。若交接内容与仓库当前代码或规范冲突，以当前仓库文件和用户最新明确指令为准，并在新的交接记录中说明差异。

接收方结束工作时应在本目录新增反向交接文档，至少写明最终提交或未提交状态、实际修改文件、已执行验证、未执行验证及原因、遗留风险、远程操作和下一步建议。
