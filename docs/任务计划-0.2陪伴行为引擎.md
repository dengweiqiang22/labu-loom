# 0.2 陪伴行为引擎任务计划

## 一、目标

在不改变桌面陪伴定位和数据隐私边界的前提下，建立可扩展、可停止、可恢复的输入与行为基础，使键盘、鼠标和手柄反馈能够逐步从直接驱动模型迁移为统一的陪伴行为。

本阶段版本基线为 `0.2.0`。不进入选择式互动、长期记忆、在线服务或自由文字聊天。

## 二、任务状态

| 编号  | 任务                     | 状态   | 验收标准                                                   |
| ----- | ------------------------ | ------ | ---------------------------------------------------------- |
| BE-01 | 建立统一瞬时输入事件契约 | 已完成 | 键盘、鼠标和手柄事件使用同一语义模型，现有模型反馈保持一致 |
| BE-02 | 完善输入监听生命周期     | 已完成 | 监听可启动、停止、重复启动和失败恢复，退出时释放资源       |
| BE-03 | 合并高频鼠标事件         | 已完成 | 鼠标移动按渲染节奏合并，不逐条进入行为层                   |
| BE-04 | 建立瞬时活动状态         | 已完成 | 仅在内存维护活跃、空闲、输入强度和最近活动状态             |
| BE-05 | 实现三种陪伴模式         | 已完成 | 安静、陪伴和活跃模式具有明确且可切换的行为约束             |
| BE-06 | 实现行为调度             | 已完成 | 支持优先级、打断、恢复、冷却和频率上限                     |
| BE-07 | 实现有限范围移动         | 已完成 | 宠物只在偏好位置附近移动，尊重锁定和屏幕边界               |
| BE-08 | 完成 Windows 与隐私验收  | 进行中 | Windows 实机稳定运行，磁盘和日志无原始输入事件             |

状态取值：`待开始`、`进行中`、`已完成`、`阻塞`。

## 三、实施顺序

1. 定义平台无关的输入事件语义，并在前端入口完成归一化。
2. 修正 Rust 输入监听的启动、停止、并发和失败恢复行为。
3. 将鼠标移动合并到受控频率，再提供给行为状态层。
4. 建立不持久化的活动、精力和好奇心等瞬时状态。
5. 在状态层之上实现陪伴模式和行为调度。
6. 最后接入有限移动，并完成 Windows 性能、稳定性和隐私验收。

## 四、数据与隐私边界

- 统一事件只存在于运行内存，不进入 Pinia 持久化 Store、日志、缓存或崩溃报告。
- 具体按键、鼠标坐标、手柄按钮和单次事件时间不得持久化。
- 行为层只消费当前状态或短时间聚合结果，不保存可还原操作过程的序列。
- 本阶段不新增长期数据字段；未来需要聚合统计时另行设计保留周期、查看和删除方式。
- 暂停输入监听后必须清除按下状态、移动目标和尚未消费的瞬时事件。

### 4.1 手柄范围调整

- 保留现有手柄输入契约、Tauri 命令、事件和展示模式，不删除或破坏已有 API。
- 当前没有明确的实体手柄使用场景，也没有可用于验收的设备，因此 `0.2` 阶段不继续投入硬件适配。
- 手柄断连、重连、型号兼容性和实体按钮验收不属于 BE-08 或本阶段完成条件。
- 后续出现明确需求和可用设备时，单独建立手柄适配任务并重新定义验收范围。

## 五、完成定义

- 三类输入具有统一、可测试的平台无关事件契约。
- 输入监听具备明确生命周期，不出现重复监听或空转占用。
- 高频输入不会直接造成渲染抖动或无界队列积压。
- 三种陪伴模式和行为调度均有自动化检查与 Windows 实机证据。
- 磁盘、日志和持久化 Store 中不存在具体按键、鼠标轨迹或单次输入事件。

## 六、当前实施结果

### 6.1 实施前基线

- 阶段开始时，Rust 分别采集键鼠和手柄事件，并通过两个 Tauri 事件发送到前端。
- 阶段开始时，前端 `useDevice` 与 `useGamepad` 分别将原始载荷直接映射为 Live2D 参数和按键贴图。
- 鼠标位置已经按 PixiJS ticker 平滑消费，但当时尚未形成统一输入语义和行为状态。
- 键鼠与手柄监听最初使用不同的生命周期语义，缺少统一的启动、停止和失败恢复约束。

### 6.2 首批范围

- 已将版本基线提升到 `0.2.0`。
- 已新增不持久化的统一输入事件类型与归一化函数。
- 键盘、鼠标和手柄入口已改为先归一化，再复用现有模型反馈逻辑。
- 已增加输入归一化单元测试，不在测试或生产日志中记录真实用户输入。

### 6.4 输入监听生命周期

- 已将版本提升到 `0.2.1`。
- 键鼠监听已移出异步命令执行器，改由唯一的后台线程负责；重复启动保持幂等，暂停时停止向前端发送事件。
- `rdev` 全局监听不提供运行中取消接口，因此键鼠线程与应用进程同寿命，退出时由系统释放；应用内暂停仍会立即清除前端按下状态和移动目标。
- 手柄监听支持启动、停止、等待线程退出和再次启动；空闲轮询增加短暂休眠，避免无事件时持续空转。
- 应用退出和手柄组件卸载时主动停止手柄线程，停止后同步清除摇杆瞬时状态。
- 监听线程使用运行守卫复位状态；初始化、线程创建或异常退出均以不包含原始输入的模块错误反馈给前端。
- 自动化已覆盖重复启动拒绝、停止后重启，以及键鼠事件暂停后恢复。
- 按已确认的范围调整，实体手柄适配和硬件复验已移出 `0.2` 阶段；现有手柄 API 与基础监听实现继续保留。

### 6.5 高频鼠标事件合并

- 已将版本提升到 `0.2.2`。
- 键盘和鼠标按钮事件继续即时发送，不改变现有动作响应语义。
- 鼠标移动事件在 Rust 内存中只覆盖一个“最新坐标”，不创建事件队列，也不保留历史轨迹。
- 独立发送线程以 16ms 周期取走一次最新坐标，将跨 Tauri IPC 的鼠标移动频率限制在约 60Hz。
- 每次取走后立即清空；暂停监听、监听结束或线程退出时也会清空尚未消费的坐标。
- 自动化已验证连续写入 1000 个坐标后只保留最后一个，以及清空后不会再产生待发送坐标。

### 6.6 v0.2.2 发布

- 本次发布包含统一输入事件契约、输入监听生命周期修正和高频鼠标移动事件合并。
- 发布前检查已覆盖前端测试、ESLint、生产构建、Rust 格式、workspace check、Rust 测试和 Windows 实际启动。
- 版本产物由 `v0.2.2` 标签触发 GitHub Actions 构建，并先进入 Draft Release 等待人工确认。

### 6.7 瞬时活动状态

- 已将版本提升到 `0.2.3`，并建立 `active`、`settling`、`idle` 三段瞬时活动状态。
- 键盘、鼠标和手柄的归一化事件共同驱动输入强度；强度随时间衰减并限制在 `0～1`。
- 活动引擎只保留强度、阶段和距最近活动的时长，不保留具体按键、坐标、控制器按钮或事件序列。
- 状态使用普通 Vue 响应式内存对象，不进入 Pinia 持久化、日志或磁盘。
- 暂停输入监听或主窗口组件退出时会停止状态刷新并清空全部瞬时活动状态。
- 自动化覆盖初始空闲、输入记录、强度衰减、高频输入上限、状态转换和重置行为。

### 6.8 陪伴模式策略

- 已完成 BE-05，版本已提升到 `0.2.4`，并建立安静、陪伴和活跃三种模式的纯策略层。
- 安静模式禁止主动行为和移动；陪伴模式采用普通动效，主动行为最短间隔 5 分钟、每小时最多 4 次、每日选择式互动最多 2 次；活跃模式采用丰富动效，主动行为最短间隔 2 分钟、每小时最多 12 次、每日选择式互动最多 6 次。
- 当前数值是低打扰优先的第一版策略上限；BE-06 行为调度只能在这些上限内执行，后续可根据 Windows 实机体验向下调整。
- 新增的 `companion.mode` 来自用户明确选择，作为本地低敏感偏好持续保存；用户可在猫咪设置中查看、修改或恢复默认陪伴模式。
- 模式偏好不包含输入事件或活动状态，不进入未来原始输入处理与聚合链路；同步范围仍保持关闭和未实现。
- 模式切换不直接覆盖用户已有的动作音效、鼠标跟随和窗口设置。
- 自动化已验证默认模式、合法值归一化、损坏配置回退，以及三种策略之间的限制关系。
- Windows 开发实例已启动并保持响应；人工切换安静和活跃模式后重启应用，所选模式均能正确保留并恢复。

### 6.9 行为调度

- 已完成 BE-06，版本已提升到 `0.2.5`，并建立不依赖 Vue、Tauri 或具体模型的内存行为调度器。
- 调度优先级从低到高为环境主动行为、活动响应、用户触发和关键系统行为；更高优先级可以立即打断当前行为，同级或低优先级进入最多 16 项的有界队列。
- 只有明确声明为可恢复的行为会在被打断后回到队列；恢复时从头重新播放，不伪造 Live2D 不支持的逐帧续播，并且不会重复占用主动行为次数。
- 主动行为同时受陪伴模式开关、全局最短间隔、行为专属冷却和滚动一小时次数限制；主动选择式互动另外受本地自然日上限限制，为 `0.3` 互动层预留统一入口。
- 调度中的当前行为、等待队列、冷却时间和频率计数全部只存在内存，应用退出或停止调度时立即清空，不进入 Pinia、日志或磁盘。
- 模型设置页触发的 Live2D 动作已经接入用户优先级调度；用户动作会使用 Live2D 强制优先级打断低优先级动作，播放结束后恢复可恢复行为。
- Live2D 播放失败会释放当前调度项并继续后续队列，避免单个模型资源错误永久卡住调度器。
- 切换或重新加载模型时会清空旧模型的当前行为和等待队列，避免已销毁动作无法回调而阻塞新模型。
- 主窗口根节点改为继承 WebView 可用尺寸，并统一禁止根页面溢出，避免小尺寸或缩放恢复时出现滚动条并挤压模型画布。
- 连续鼠标视线参数、按键贴图和手柄轴参数仍直接响应，不进入离散行为队列。

### 6.10 有限范围移动

- 已完成 BE-07，版本已提升到 `0.2.6`；平台无关的移动规划器只根据偏好位置、当前显示器边界、窗口尺寸、陪伴模式和锁定状态生成临时目标。
- 安静模式禁止主动移动；陪伴模式移动半径不超过 `36 px`，活跃模式不超过 `72 px`，目标始终容纳在偏好位置所在显示器内，不根据鼠标所在显示器跨屏移动。
- 主窗口每 30 秒只在用户处于空闲状态时尝试提出移动请求；请求继续服从 BE-06 的 5 分钟或 2 分钟最短间隔、每小时上限和有界调度，不建立独立的高频行为队列。
- 单次移动使用约 800 毫秒、50 毫秒一帧的低频平滑位移；用户按下宠物窗口、切换陪伴模式或开启位置锁定时会立即取消当前移动和等待任务。
- 自动移动坐标只存在于运行内存，不写回 `windowState`；用户手动拖动后的最终坐标仍会成为新的本地偏好位置并在下次启动时恢复。
- 新增 `window.lockPosition` 是用户主动设置的本地布尔偏好：用途是禁止主动移动，保存粒度仅为开关状态，保留到用户再次修改或清除应用数据，可在猫咪设置中查看、修改，也可通过恢复默认设置或删除本地应用数据清除。
- 自动化已覆盖安静与锁定禁止移动、两种模式的范围差异、显示器边界和窗口大于显示器的退化情况；前端测试、ESLint、生产构建、Rust 格式、workspace check 和 Rust 测试均通过。

### 6.11 Windows 与隐私验收进度

- 已开始 BE-08。`v0.2.6` Windows 开发实例启动并保持响应，短时空闲采样未发现异常 CPU 或内存占用。
- 对实际 `tauri-plugin-pinia` 开发存储进行键名和模式检查：只发现窗口位置、用户设置、模型配置和快捷键映射；未发现键盘按下/释放、鼠标移动、设备事件、手柄事件、鼠标轨迹或运行时 `pressedKeys` 数据。
- 对实际应用日志进行不回显内容的模式检查：未发现鼠标移动、键盘事件、设备事件、手柄事件或坐标记录；两处包含 `Key` 的既有日志均属于更新或签名信息，不是用户输入。
- 尚需完成人工可视验收：观察陪伴/活跃模式的有限移动、锁定后停止、手动拖动后围绕新位置移动、多显示器不跨屏，以及较长运行期间 Windows 光标无延迟回归。
