# 0.1 项目基线任务计划

## 一、目标

在不改变桌面陪伴宠物核心行为的前提下，将项目从上游 BongoCat 基线隔离为 labu-loom，并建立可重复的 Windows 开发与验证入口。

本阶段不实现陪伴行为引擎、记忆系统或正式发布服务。

## 三、实施顺序

### 3.1 应用身份隔离

- 将前端包名、Rust 包名和库名调整为 labu-loom。
- 将 Tauri 产品名、窗口标题和平台 identifier 调整为 labu-loom 专属值。
- 更新界面内仍然出现的旧产品名称。
- 更新项目说明，同时保留 `LICENSE` 和上游项目归属。

兼容性说明：Tauri identifier 从 `com.ayangweb.BongoCat` 切换后，系统会将其视为不同应用，本地配置目录、开机启动项和安装身份不会自动继承。0.1 阶段不迁移上游应用数据，后续如需导入旧配置，必须设计显式、可回滚的迁移流程。

### 3.2 切断旧更新链路

- 删除旧 HTTP 更新端点、代理下载地址、公钥和访问键。
- 在新更新地址和签名方案完成评审前，移除旧自动检查、手动检查及下载更新入口。
- 评审完成后，仅恢复用户主动触发的更新检查；默认不弹出更新提醒。

### 3.3 固定工具链

- 固定 Node、pnpm 和 Rust 版本。
- 将 `lint` 设为只检查，另设显式的自动修复命令。
- 保持锁文件作为依赖安装的唯一基线。

### 3.4 验证与回写

- 执行 `corepack pnpm lint`。
- 执行 `corepack pnpm build`。
- 执行 `cargo fmt --all -- --check`。
- 执行 `cargo check --workspace --locked`。
- Windows 实际运行未执行时必须保持 BL-05 未完成，并写明原因。

## 四、隐私与数据边界

- 本阶段不得新增任何输入数据持久化。
- 日志不得包含具体按键、鼠标坐标序列或输入载荷。
- 应用标识变化不得通过静默扫描旧数据目录来迁移用户数据。
- 后续迁移必须允许用户知情选择，并提供失败回滚路径。

## 五、完成定义

- 已完成的任务具有对应代码或配置证据。
- 所有实际执行的验证命令和结果已回写本文档。
- 未完成的 Windows 实机验证、发布地址和签名方案保持显式待办或阻塞。
- 工作区中不存在意外生成的发布产物、密钥、日志或用户数据。

## 六、本轮实施结果

### 6.1 已完成

- 前端包、Rust 包和 Tauri 应用身份已统一为 `labu-loom`，平台 identifier 调整为 `com.labuloom.desktop`。
- 主窗口标题、托盘内部标识和各语言权限说明已替换旧产品名称。
- 已移除旧更新端点、公钥、访问键和自动检查组件，不再访问上游更新服务。
- 已接入 labu-loom 专用 Tauri 更新公钥、GitHub Releases `latest.json` 地址、updater 插件和用户主动触发的检查更新入口；更新产物生成已开启。
- 已增加 `.nvmrc`、`packageManager`、Node/pnpm engines 和 `rust-toolchain.toml`。
- `lint` 已改为只检查，自动修复由 `lint:fix` 显式触发。
- 图标构建脚本改用 Node 24 原生 TypeScript stripping，避免 `tsx` 临时目录初始化失败。
- README 已改为 labu-loom 当前产品说明，并保留 BongoCat 上游归属和许可证入口。
- Windows 实机已验证透明主窗口、托盘、偏好设置与单实例唤起；新增可持久化的“键盘与鼠标监听”开关。
- 监听关闭后，Rust 输入回调会立即丢弃事件；恢复后重新接收事件，不保存具体按键、鼠标坐标或事件时间。
- 正式仓库已确认为 `https://github.com/dengweiqiang22/labu-loom`；发布工作流已收敛为 Windows x64 GitHub Releases，旧 UpgradeLink 和 Gitee 同步任务已删除。
- 发布与更新的地址、Secrets 名称、签名分层和人工发布门禁已记录在 `docs/发布与更新方案.md`。
- labu-loom 专用更新私钥已加密保存在用户目录，随机密码以 Windows DPAPI 密文备份；私钥和密码均未写入工作区。

- 同一干净副本中，`corepack pnpm lint` 和 `corepack pnpm build`：通过；复验副本随后已清理。
- 当前工作区 `corepack pnpm lint`：通过。
- 当前工作区 `corepack pnpm build`：通过；Vite 提示主包体积超过 500 kB，属于已有性能待办。
- `cargo fmt --all -- --check`：通过。
- `cargo check --workspace --locked`：通过。

- Tauri 和 capability JSON 解析：通过。
- 旧更新端点、访问键、更新插件及旧 crate 引用扫描：未发现残留。
- Windows `corepack pnpm tauri dev`：启动通过；透明宠物主窗口、托盘图标、偏好设置和第二实例唤起偏好设置均通过。
- 偏好设置实机点击“键盘与鼠标监听”：持久化状态依次变为 `false` 和 `true`，关闭与恢复通过。

### 6.3 环境问题与遗留风险

- 原 Codex fallback pnpm 环境中的安装停滞未在普通终端复现，归因于该任务的临时 runtime 和既有 `node_modules` 状态，不需要写入项目级 linker 规避配置。
- 开机自启动开关只确认了界面存在，未修改当前 Windows 的登录启动状态，避免为了验收改变用户系统设置。
- identifier 变化会创建新的应用数据与安装身份；本轮不迁移上游 BongoCat 数据，也不静默扫描其数据目录。
- GitHub Actions Secrets 尚未远程写入，发布 workflow 也尚未通过真实标签运行；首次远程发布前需要按 `docs/发布与更新方案.md` 完成 Secrets 配置。
- 0.1 按用户确认暂不采购或配置 Windows Authenticode 证书，安装包可能触发 SmartScreen 提示；Tauri 更新签名不受此决定影响。
- 由于当前尚无上一正式版本，完整的“旧版本读取 `latest.json` 并升级到新版本”只能在连续两个正式版本具备后验收。
