# 0.4 回忆与体验完善任务计划

## 一、目标

在 `0.3.7` 已有的日、周、月聚合和结构化记忆之上，建立面向用户的共同回忆体验，并完善连续工作暗示、可选休息提醒、多显示器和窗口边界。核心体验继续保持离线、本地、低打扰，不引入自由文字聊天、在线模型或生产力评分。

本阶段版本基线为 `0.4.0`，原计划完成版本为 `0.4.8`；Windows 实机验收发现的问题在 `0.4.9` 中修复。

## 三、实施顺序

1. RE-01 先提供不依赖界面的只读展示模型，作为页面和自然总结的共同数据源。
2. RE-02 接入现有记忆页，默认展示共同回忆，同时保留完整的查看、修改、忘记和清除入口。
3. BUG-01 先修复实机发现的互动入口点击问题，再继续新的体验能力。
4. RE-03 至 RE-05 依次完成自然表达、动作暗示和用户主动开启的明确提醒。
5. RE-06 可与表达能力并行开发，但必须在最终 Windows 验收前完成。
6. RE-07 统一处理界面细节、错误恢复和构建体积，RE-08 完成阶段收口。

## 五、产品与数据边界

- 共同回忆不是生产力仪表盘，不显示分数、排名、打卡、完成率或负面评价。
- 展示模型只消费日、周、月聚合与结构化记忆，不读取应用名称、窗口标题、屏幕、文档或剪贴板。
- 共同回忆最多展示少量近期重点；完整的修改、忘记和清除能力继续放在记忆管理视图。
- 自然总结使用代码内置的固定模板和结构化参数，不保存最终渲染文案。
- 连续工作时长只允许在当前运行期间短暂存在于内存；长期存储仍保持日级聚合。
- 明确休息提醒默认关闭，安静模式、窗口穿透或用户关闭互动时不得出现。
- `WIN-01` 微信输入法 CrashRpt 弹窗继续作为外部问题观察，在最终实机验收中回归。

## 六、完成定义

- 用户可以看到温和、可忽略的共同回忆，而不是原始数据表。
- 所有自然表达都能追溯到结构化记忆或聚合周期，并支持现有删除流程。
- 关闭统计或清除数据后，共同回忆和总结同步消失，不保留派生副本。
- 提醒和动作暗示不会破坏拖动、穿透、安静模式或行为调度上限。
- 显示器布局、缩放或连接状态变化后，宠物与设置窗口仍能恢复到可见区域。
- Windows 日志、Store 和崩溃诊断中不出现原始键鼠事件或自由文字。

## 七、当前实施结果

### 7.1 共同回忆展示模型

- 已完成 RE-01，版本提升到 `0.4.0`；新增纯函数展示模型，统一组合日、周、月聚合与结构化记忆。
- 模型只计算陪伴记录覆盖天数、既有聚合累计、可用周期范围和最多 4 条近期结构化记忆，不新增 Store 字段或派生持久化副本。
- 近期记忆按日级更新时间稳定排序；输入数组和记忆对象保持只读，不会因为页面展示改变原始数据。
- 空数据返回明确空态，数据清除后无需额外清理展示缓存；后续页面与自然总结共用这一数据入口。

### 7.2 共同回忆页面

- 已完成 RE-02，版本提升到 `0.4.1`；记忆页面默认展示共同回忆，并保留独立的记忆管理视图。
- 页面只展示陪伴记录覆盖天数、可用聚合周期和最多 4 条近期结构化记忆，不展示分数、原始输入或精确活动时间线。
- 既有分类修改、单条忘记、分类清除和全部清除入口保持不变；无数据时展示温和空态，不创建派生持久化副本。
- 已补齐简体中文、繁体中文、英文、葡萄牙文和越南文文案，并在 Windows 调试实例中确认应用进程正常响应。

### 7.3 主动互动入口点击修复

- BUG-01 使用 `0.4.2`；实机安装版 `0.3.7` 中出现互动入口可见但点击后不展示选择气泡。
- 已确认本机持久化设置为互动开启、窗口穿透关闭，Windows 主窗口的原生点击穿透样式也处于关闭状态，因此问题不属于用户设置或窗口穿透残留。
- 根因是主窗口使用了 `InteractionBubble` 标签却没有导入组件，运行时把它渲染为空的未知 HTML 元素；点击状态正常打开并隐藏入口，但没有可见气泡。
- 已显式导入互动气泡组件，没有改动既有模型拖拽结构；Windows WebView2 实机点击后能显示完整气泡和 3 个选项，关闭按钮与“暂时不回应”均能正常结束互动。
- 自动化交互测试、调度测试、ESLint、前端生产构建、Rust 格式和 workspace check 已通过。

### 7.4 宠物视角自然总结

- 已完成 RE-03，版本提升到 `0.4.3`；新增纯函数 `createPetPerspectiveSummary`，只从 `RecollectionOverview` 选择固定模板键和数值参数。
- 共同回忆页面增加“宠物眼里的我们”卡片；文案全部走五种语言 i18n，不在业务函数中硬编码完整句子，也不持久化渲染结果。
- 空数据返回 `null` 并继续展示既有空态；清除聚合或记忆后总结随 overview 同步消失。
- 已补齐总结模型单元测试；Windows 开发实例页面展示与清除联动留给 Codex 验收。

### 7.5 连续工作动作暗示

- 已完成 RE-04，版本提升到 `0.4.4`；`ActivityTracker` 增加仅内存的 `continuousActiveForMs`，空闲后清除。
- 新增 `shouldOfferWorkHint` / `pickWorkHintMotion` 与 `useWorkHint`，达到阈值后通过既有 `scheduleProactiveMotion` 播放休息类动作。
- 安静模式或模型缺少匹配动作时跳过；不新增 Store 字段，不保存精确工作时间线。

### 7.6 可选明确休息提醒

- RE-05 功能代码已实现并将版本提升到 `0.4.5`；新增 `restRemindersEnabled`（默认关闭）与 `rest-reminder` 选择式模板。
- 同一次连续活跃段内最多主动提醒一次；安静模式、穿透或关闭互动时不出现。
- 记忆 schema 升至 5，旧设置迁移时安全补齐默认值。
- Windows 加速实机验收已通过：临时将连续活跃阈值、检查周期和活跃模式冷却缩短后，用户确认桌宠上方出现“已经忙了一段时间，要不要稍微休息一下？”提示；验收后已恢复 25 分钟阈值、60 秒检查周期和 2 分钟冷却。
- 验收期间确认界面缺失并非提醒模板问题，而是 Vite 热更新替换 canvas 后 Pixi 应用仍绑定旧画布；现已在画布变化和页面卸载时完整重建 Live2D 渲染器，热更新后用户确认角色正常显示。

### 7.7 多显示器与窗口边界

- 已完成 RE-06，版本提升到 `0.4.6`；新增 `domain/window/bounds` 处理工作区钳制、负坐标匹配和断屏后的可见恢复。
- `useWindowState` 按窗口所在显示器钳制，显示器消失时回落到首个可用屏工作区中心；焦点变化时再次钳制。
- `getCursorMonitor` 改为物理坐标查询；有限移动同样改用工作区边界。

### 7.8 界面、性能与异常体验

- 已完成 RE-07，版本提升到 `0.4.7`；偏好页懒加载，并拆分 antd / vue-vendor / live2d 分包。
- 用户可见错误改为稳定本地化文案；技术细节继续只写日志。
- 生产构建主入口体积已下降，500 kB 警告仍可能出现，留待 RE-08 实机观察。

### 7.9 Windows 与隐私验收

- RE-08 已在 `0.4.9` 完成；既有 `0.4.8` 本机数据可被 `0.4.9` 开发实例正常读取，桌宠、偏好设置、共同回忆和选择式互动均保持可用，本次没有新增存储字段或迁移步骤。
- 核心陪伴、共同回忆、互动、行为和记忆链路均为本地实现；代码扫描确认只有用户主动触发的更新检查访问网络，网络失败由本地化错误提示降级处理，不会阻塞应用或导致崩溃。
- 共同回忆有数据、空态、自然总结及全部清除由完整前端测试覆盖；清除测试确认聚合、结构化记忆和抑制标记会同时移除。为避免破坏用户真实数据，本轮没有执行本机数据删除。
- 连续工作暗示与明确休息提醒的策略测试通过；Windows 加速实机验收确认角色正常显示且主动开启后出现休息提示，默认关闭、安静模式、穿透、互动关闭、频率上限和段内去重继续由策略门控。
- 多显示器自动化覆盖负坐标、工作区钳制、显示器消失后的首屏回落和小于宠物窗口的边界；物理坐标链路覆盖 DPI 缩放。未改动用户真实显示器连接与缩放配置，实体多屏仍作为后续非阻塞回归项。
- 完整前端测试 79 项、ESLint、生产构建、Rust 格式、workspace check、5 项 Rust 测试及全目标严格 Clippy 均通过；生产构建主入口约 193 kB，`live2d` 与 `antd` 独立分包仍超过 500 kB，属于已评估的非阻塞警告。
- Windows 隐私脚本检查 12 个实际 Store 文件和 1 个日志文件并通过；未发现具体按键、鼠标轨迹、单次事件载荷或自由文字持久化。
- `WIN-01` 仍确认是强制终止开发进程时可能触发的第三方微信输入法 CrashRpt 行为；正常运行和本轮实机验收未复现，不阻塞阶段完成。

## 八、阶段结论

`0.4` 阶段 RE-01 至 RE-08 已全部完成。共同回忆、自然总结、连续工作暗示、可选休息提醒、多显示器边界和 Windows 隐私约束形成闭环；`0.4.9` 作为本阶段最终修复版本进入稳定分支发布。
