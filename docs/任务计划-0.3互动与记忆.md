# 0.3 互动与记忆任务计划

## 一、目标

在 `0.2` 陪伴行为引擎之上增加低打扰的选择式互动和本地活动聚合，为后续结构化记忆提供可靠数据基础。核心体验保持离线可用，不引入自由文字聊天、在线模型或云端同步。

本阶段版本基线为 `0.3.0`。本轮先完成 IM-01 至 IM-04，周月压缩、结构化记忆生成和记忆管理留在后续批次。

## 二、任务状态

| 编号  | 任务                     | 状态   | 验收标准                                                       |
| ----- | ------------------------ | ------ | -------------------------------------------------------------- |
| IM-01 | 定义数据模型与迁移       | 已完成 | 数据具有版本、默认值、校验、迁移、保留上限和清除入口           |
| IM-02 | 实现选择式互动气泡       | 已完成 | 每次 2～4 个选项，允许关闭或不回应，不提供自由文字输入          |
| IM-03 | 接入互动调度             | 已完成 | 主动互动服从模式、冷却、每日上限、穿透状态和用户忽略偏好       |
| IM-04 | 实现每日活动聚合         | 已完成 | 只保存按日累计结果，关闭统计后不再累计，不持久化原始输入       |
| IM-05 | 实现周月分层压缩         | 已完成 | 日数据保留 30 天、周数据保留 12 个月，压缩后删除被替代数据     |
| IM-06 | 建立结构化记忆           | 待开始 | 从明确选择和聚合趋势生成习惯、偏好、情境和关系记忆             |
| IM-07 | 增加记忆管理             | 待开始 | 支持查看来源、结构化修改、忘记、分类清除和全部清除             |
| IM-08 | 完成 Windows 与隐私验收  | 待开始 | 升级、离线、清除和磁盘检查通过，日志与存储无原始输入           |

状态取值：`待开始`、`进行中`、`已完成`、`阻塞`。

## 三、本轮实施顺序

1. 建立 `schemaVersion`、默认设置、迁移函数和独立持久化 Store。
2. 先实现用户主动打开的选择式气泡，再接入低频主动调度。
3. 互动调度复用 `0.2` 的优先级、冷却和频率上限，不建立第二套调度器。
4. 活动聚合只消费内存状态，按粗粒度累计并定时写入当日汇总。

## 四、已确认产品约束

- 选择式互动默认开启；键盘和鼠标活动统计分别默认关闭，必须由用户主动开启。
- 互动只使用内置问题和 2～4 个结构化选项，永远允许关闭或不回应。
- 不回应不会被解释为负面关系，只用于降低以后主动互动频率。
- 结构化记忆保存类型和值，不保存自由文字；界面根据当前语言渲染自然表达。
- 窗口穿透开启时不展示需要点击的主动互动。
- 本阶段不读取窗口标题、应用名称、屏幕、文档或剪贴板内容。

## 五、数据与隐私设计

### 5.1 设置字段

- `interactionsEnabled`：控制选择式互动，来源为用户设置，保存为单个布尔值，保留到用户修改或清除应用数据，可在猫咪设置中查看和修改，不进入未来同步。
- `keyboardStatsEnabled`：控制键盘活动聚合，来源为用户设置，保存为单个布尔值，默认关闭，可在猫咪设置中查看和修改，不进入未来同步。
- `mouseStatsEnabled`：控制鼠标活动聚合，来源为用户设置，保存为单个布尔值，默认关闭，可在猫咪设置中查看和修改，不进入未来同步。

### 5.2 每日聚合

- 仅保存本地自然日、键盘活跃秒数、鼠标活跃秒数、空闲秒数、连续活动区间数，以及互动展示、回应和忽略的累计次数。
- 不保存具体按键、按键次数、鼠标坐标、事件序列、单次事件时间或分钟级时间线。
- 内存累加器以粗粒度采样状态，最多每 5 分钟写入一次；异常退出最多损失尚未刷新的短时累计。
- 每日数据最多保留最近 30 天；IM-05 接入周汇总后删除已经被周数据替代的过期日数据。

### 5.3 迁移与回滚

- `0.3.0` 新建独立 `memory` Store，初始 `schemaVersion` 为 `1`；旧版本不存在该 Store，因此迁移只需安全补齐缺失字段并丢弃未知字段。
- 所有数值在载入时归一化为非负整数，非法日期、未知记忆类型和任意额外字段不进入运行状态。
- 回滚到 `0.2.x` 时旧版本不会读取该 Store，不影响猫咪、窗口和通用设置；重新升级后仍可继续迁移合法数据。
- 用户关闭某类统计后立即清除该类尚未写入的内存累计；已聚合数据在后续记忆管理页支持分类或全部清除。

## 六、完成定义

- 互动气泡不会阻塞宠物拖动、模型渲染或窗口关闭。
- 主动互动在安静模式、窗口穿透或用户关闭互动时不会出现。
- 应用重启不能绕过每日互动上限。
- 活动聚合默认不采集；开启后只产生按日汇总。
- 自动化覆盖迁移、非法数据、互动选择、调度限制、跨日和关闭统计。
- Windows 实际存储和日志中不存在具体按键、鼠标轨迹、单次事件或自由文字。

## 七、当前实施结果

### 7.1 实施前基线

- `0.2.7` 已提供统一瞬时输入事件、三段活动状态、三种陪伴模式和统一行为调度。
- 行为调度已经支持主动互动频率类型与每日上限，但计数只存在内存，应用重启后会重置。
- 当前仅有猫咪、通用、模型、快捷键和窗口状态 Store，尚无统计或记忆持久化结构。
- 主窗口鼠标按下会立即开始拖动，互动入口必须隔离指针事件，不能破坏现有拖动体验。

### 7.2 数据模型与迁移

- 已完成 IM-01，版本提升到 `0.3.0`；新增独立 `memory` Store 和纯函数迁移层，当前 schema 版本为 `1`。
- 选择式互动默认开启；键盘和鼠标活动统计分别默认关闭，三个设置均已在猫咪设置页提供明确说明和独立开关。
- 日汇总只允许非负整数累计值和本地自然日，迁移时按日期排序并限制为最近 30 条；非法日期、未知字段和原始输入载荷会被丢弃。
- 结构化记忆契约只接受预定义类别、类型、值、来源和日级来源区间，不接受任意自由文字。
- `clearAllData` 已提供统一的本地统计和记忆清除入口；IM-07 将其接入面向用户的记忆管理界面。
- 回滚到 `0.2.x` 时不会读取新增 Store；重新升级会重新执行幂等归一化，不修改原有猫咪、窗口、模型或通用设置。
- 4 项 schema 测试通过；连同既有测试共 31 项，ESLint、前端生产构建、Rust 格式和 workspace check 通过。

### 7.3 选择式互动气泡

- 已完成 IM-02，版本提升到 `0.3.1`；主窗口提供低存在感的用户主动互动入口，关闭互动或开启窗口穿透时不会显示。
- 首个内置互动包含 3 个预设选项，其中“暂时不想回应”和关闭按钮都允许无负担退出；组件没有文本框，也不接收任意回答。
- 气泡及按钮隔离鼠标按下、移动和右键事件，不会触发主窗口拖动或弹出宠物菜单；模型渲染层和已有输入响应保持不变。
- 互动定义使用稳定标识和本地化键，后续只保存结构化选择标识，不保存界面文案。

### 7.4 主动互动调度

- 已完成 IM-03，版本提升到 `0.3.2`；主动互动作为 `interaction` 频率任务接入统一行为调度器，与主动动作共享优先级、冷却和每小时上限。
- 仅在宠物可见、窗口非穿透、互动开关开启且用户处于空闲状态时尝试展示；安静模式通过既有策略将每日上限设为 0。
- 主动展示、回应和忽略按本地自然日写入汇总，应用重启后仍会从持久化计数判断每日上限。
- 至少出现 2 次后才根据忽略比例将冷却扩大为 2 倍或 3 倍；单次不回应不会被当作稳定偏好。
- 用户操作、切换穿透或关闭互动会中止正在等待的主动气泡并释放调度任务，不保留任意回答文本。

### 7.5 每日活动聚合

- 已完成 IM-04，版本提升到 `0.3.3`；键盘与鼠标事件只向内存累加器传递来源分类，不传递具体按键、坐标或原始载荷。
- 累加器每秒粗粒度采样，单次最长只计 5 秒，最多每 5 分钟把完整秒数合并到本地自然日汇总；跨日时先刷入前一日并清空瞬时状态。
- 键盘与鼠标分别服从用户开关；关闭某类统计会立即清除该类尚未写入的累计，关闭输入监听则停止两类统计。
- 持久化层只累加键盘活跃秒数、鼠标活跃秒数、空闲秒数和活动区间数，并继续只保留最近 30 个有效自然日。
- 自动化覆盖来源聚合、关闭后丢弃、默认不采集和跨日刷新；磁盘隐私扫描继续检查 Store 与日志中不存在原始输入字段和事件文本。

### 7.6 周月分层压缩

- 已完成 IM-05，版本提升到 `0.3.4`，memory schema 升级到 `2`；旧 schema 会自动补齐周汇总和月度趋势集合。
- 超过最近 30 个自然日的日汇总按周一边界合并为周汇总，来源日记录随即删除；超过最近 12 个日历月窗口的周汇总继续并入月度趋势并删除。
- 周、月层只保存覆盖天数和既有累计字段，不新增小时段、单次时间或可还原操作过程的维度；月度趋势允许长期保留。
- 压缩在初始化和新增自然日时执行，重复执行不会重复累计；跨版本回滚时旧版忽略新增集合，重新升级后仍可规范化读取。
