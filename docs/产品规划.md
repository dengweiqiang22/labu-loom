# labu-loom 产品规划

## 文档信息

- 文档版本：0.1
- 产品阶段：方向确认
- 目标平台：Windows
- 核心定位：桌面陪伴宠物

## 一、产品定位

labu-loom 是一款 Windows 优先、本地运行的桌面陪伴宠物。

产品主要陪伴用户度过无聊或重复的工作时间，通过动作、状态变化和低频互动建立持续的陪伴感。它不是聊天机器人、效率管理工具、直播工具或通用角色创作平台。

未来可以扩展桌面助手能力，但助手能力不得改变桌面宠物的核心定位，也不应成为首个版本的依赖。

## 二、产品原则

### 2.1 陪伴优先

- 宠物默认安静存在，不持续占用用户注意力。
- 主动行为应自然、低频，并且可以被关闭。
- 不通过签到、任务、等级或经验值制造使用压力。
- 用户长时间不互动时，宠物不会受到惩罚或进入负面状态。

### 2.2 稳定人格与自适应关系

- 官方宠物具有稳定、可辨识的核心人格。
- 宠物可以逐渐适应用户的作息、互动频率和打扰偏好。
- 成长表现为行为默契和表达变化，不显示关系等级或成长数值。
- 重置关系记忆不会改变角色的核心人格。

### 2.3 本地优先与最小化记录

- 核心陪伴、动作反馈和记忆能力应当能够离线运行。
- 只收集实现功能所必需的数据。
- 不读取当前应用、窗口标题、屏幕内容或文档内容。
- 不持久化具体按键、输入内容、鼠标轨迹和单次输入事件。
- 未来可以提供用户主动开启的加密同步，默认仍为本地保存。

### 2.4 用户可控

- 用户可以随时切换陪伴模式。
- 用户可以暂停键盘和鼠标监听。
- 用户可以查看系统整理后的记忆，并修改、忘记或全部清除。
- 普通界面不直接展示数据库、原始事件和内部技术数据。

## 三、陪伴模式

### 3.1 安静模式

- 只响应必要的用户操作。
- 不主动显示互动气泡。
- 减少声音、位移和高频动画。
- 默认锁定宠物位置。

### 3.2 陪伴模式

- 作为默认模式。
- 允许低频的待机、观察、犯困、伸懒腰等主动行为。
- 可以偶尔发起一次选择式互动。
- 根据用户的忽略和接受情况自动调整互动频率。

### 3.3 活跃模式

- 提高动作和互动频率。
- 允许更多动作组合和有限范围移动。
- 仍需设置每小时和每日互动上限，避免持续打扰。

## 四、角色与模型策略

- 官方宠物承担完整的性格、动作、状态和品牌体验。
- 首期继续使用现有模型验证行为系统，架构稳定后再制作官方角色。
- 保留外部 Live2D 模型导入能力，但不把模型创作平台作为主要方向。
- 外部模型根据自身资源和能力自然降级，不要求支持官方模型的全部行为。

模型能力分为两层：

1. 官方模型：支持完整动作、表情、情绪状态和陪伴行为。
2. 导入模型：至少支持基础显示、鼠标跟随和动作映射；缺少资源时跳过对应行为。

## 五、交互设计

### 5.1 交互形式

核心产品不提供自由文字输入。需要用户表达时，使用情境化选择：

```text
宠物：今天看起来很忙呀。

[还在专注] [有点累] [只是发呆] [不回应]
```

### 5.2 交互规则

- 每次提供二至四个选项。
- 永远允许忽略、关闭或不回应。
- 单次互动结束后不连续追问。
- 不把用户未回应解释为负面态度。
- 用户连续忽略某类互动后，自动降低该类互动频率。
- 用户可以点击宠物主动触发互动。
- 陪伴模式允许宠物根据情境低频发起互动。

### 5.3 工作与休息表达

- 默认通过打哈欠、趴下、伸懒腰等动作间接表达。
- 陪伴模式可以偶尔询问是否休息。
- 系统通知、倒计时和明确休息提醒默认关闭。
- 用户主动开启后，宠物才承担明确提醒职责。

## 六、情绪与行为

宠物拥有轻量内部状态，例如：

- 情绪
- 精力
- 好奇心
- 熟悉程度
- 当前互动意愿

这些状态只用于驱动行为，不显示数值、进度条或健康状态。宠物可以自行休息和恢复，不要求用户喂食、清洁或完成日常任务。

行为系统需要支持：

- 行为优先级
- 行为打断与恢复
- 主动行为冷却时间
- 互动频率上限
- 模式差异
- 用户偏好适应
- 情绪和精力对动作的影响

## 七、桌面活动范围

- 默认停留在用户放置的位置。
- 可以在当前位置附近做小范围移动、探头、转身或趴下。
- 不擅自跨越整个屏幕或频繁遮挡工作内容。
- 用户拖动后，将新位置视为偏好区域。
- 支持锁定位置；安静模式默认不主动移动。
- 多显示器、任务栏和窗口边缘互动作为后续增强。

## 八、键盘、鼠标与手柄反馈

### 8.1 使用模式

- 默认模式强调自然陪伴反馈。
- 保留键盘展示模式。
- 保留手柄展示模式。

### 8.2 实时动作

键盘和鼠标事件可以用于：

- 视线跟随鼠标位置。
- 头部和身体朝向变化。
- 根据鼠标速度触发好奇、追逐或受惊动作。
- 根据键盘输入节奏播放左右手敲击和专注动作。
- 根据空闲时间切换待机、犯困和休息状态。

具体按键值可以在内存中短暂用于实时动作映射，但处理完成后必须丢弃，不得写入磁盘。

## 九、数据与记忆

### 9.1 数据处理流程

```text
键鼠原始事件
    ↓
内存中的实时动作映射
    ↓
当日聚合统计
    ↓
原始事件立即丢弃
```

### 9.2 允许保存的数据

- 键盘活动时长和整体节奏。
- 鼠标活动时长和整体强度。
- 空闲时长。
- 连续工作区间。
- 宠物互动次数。
- 选择式互动偏好。
- 经提炼的习惯、关系和情境记忆。

### 9.3 禁止保存的数据

- 具体按键及其序列。
- 用户输入的文字内容。
- 单次键鼠事件时间。
- 完整鼠标移动轨迹。
- 应用名称和窗口标题。
- 屏幕、文档和剪贴板内容。
- 能够还原用户具体操作过程的数据。

### 9.4 保存周期

- 原始事件：处理完成后立即删除。
- 每日统计：保留最近三十天。
- 周统计：保留最近十二个月。
- 月度趋势：长期保留。
- 语义记忆：根据重要性保留，并允许随时间淡化。

### 9.5 记忆类型

- 习惯记忆：常见工作和休息节奏。
- 偏好记忆：喜欢的陪伴方式和互动频率。
- 情境记忆：由选择式互动形成的阶段性信息。
- 关系记忆：长期互动形成的默契和表达变化。

## 十、数据展示与共同回忆

默认不提供生产力仪表盘，不评价用户是否足够努力。

宠物应当将数据转化为自然表达，例如：

- “今天陪你忙了很久。”
- “最近下午好像更容易累。”
- “这几天我们的安静时间变多了。”

产品可以提供一个可选的“共同回忆”页面：

- 展示经过整理的陪伴片段。
- 展示温和的长期趋势。
- 允许修改或忘记某条记忆。
- 允许按类别清除记忆。
- 允许一键删除全部本地及同步数据。
- 不展示原始数据库、事件日志、向量和内部置信度。

## 十一、平台策略

- Windows 是首要开发和验收平台。
- 键鼠监听、透明窗口、置顶、权限和多显示器体验优先在 Windows 完善。
- macOS 和 Linux 暂时不作为功能一致性要求。
- 公共业务层尽量保持平台无关，为未来适配保留空间。

## 十二、版本路线

### 0.1 项目基线

- 完成 labu-loom 品牌与应用身份隔离。
- 替换原项目的更新地址、签名和发布配置。
- 固定 Node、pnpm 和 Rust 工具版本。
- 增加类型检查、Rust 检查和基础测试。
- 整理 Windows 权限提示与启动流程。

### 0.2 陪伴行为引擎

- 统一键盘、鼠标和手柄输入事件。
- 建立输入监听的启动、停止和错误恢复机制。
- 对高频鼠标事件进行合并或限频。
- 实现情绪、精力和好奇心状态。
- 实现安静、陪伴和活跃模式。
- 实现行为优先级、打断和恢复。
- 实现固定位置与附近有限移动。

### 0.3 互动与记忆

- 实现选择式互动气泡。
- 实现主动互动频率控制。
- 实现每日活动聚合。
- 实现日、周、月分层压缩。
- 实现习惯、偏好和关系记忆。
- 实现记忆查看、修改、忘记和清除。

### 0.4 回忆与体验完善

- 实现共同回忆页面。
- 实现宠物视角的自然总结。
- 完善连续工作后的动作暗示。
- 增加可选的明确休息提醒。
- 完善多显示器和窗口边界处理。

### 0.5 官方角色

- 根据已稳定的行为协议制作官方宠物。
- 定义官方模型的动作、表情和参数规范。
- 建立外部模型能力声明与自然降级机制。
- 完善模型导入校验和错误提示。

### 后续扩展

- 用户主动开启的加密同步。
- 桌面助手能力。
- 更丰富的长期关系记忆。
- Windows 体验稳定后的其他平台适配。

## 十三、暂不进入首期范围

- 自由文字聊天。
- 在线大模型依赖。
- 直播弹幕和礼物系统。
- 通用插件市场。
- 完整角色创作平台。
- 等级、经验、签到和任务系统。
- 默认开启的效率统计与工作排名。
- 屏幕内容、窗口标题和应用使用记录。

## 十四、首期成功标准

- 宠物能够连续稳定运行，不明显影响日常工作性能。
- 键鼠输入能够及时映射为自然动作。
- 陪伴模式的主动行为不会形成明显打扰。
- 用户能够随时暂停监听和清除记忆。
- 磁盘中不存在具体按键、鼠标轨迹或单次输入事件记录。
- 即使没有网络，核心陪伴体验仍然完整可用。
